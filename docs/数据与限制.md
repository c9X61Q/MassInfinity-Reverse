# 数据字典与已知限制

## data/ 里的文件

### `recovered.jsonl.gz`
每一行一个方法：

```json
{
  "mvid": "fdc9b55eb65440ad966d0f9697aa6981",   // 所属模块 MVID
  "token": "060013c8",                          // MethodDef token（源模块内）
  "type": "ZYXDNGuarder", "method": "Startup", "sig": "void Startup()",
  "kind": "real",                               // real / vm / tail
  "maxStack": 8,
  "il": "7eb00800042c012a0028c613000680b0...",  // 原始 IL（hex）
  "localsCount": 1,                             // 从 IL 指令边界推出的局部槽位数
  "ehCount": 3,
  "eh": [ {"flags":0,"tryOff":9,"tryLen":12,"hOff":21,"hLen":3,"tok":16778032} ]
}
```

### `map.txt.gz`
`MethodDesc十六进制 | MVID | token | 类型 | 方法 | 签名`
—— 只在**同一批次运行**内有效（MethodDesc 地址每次进程都变）。

### `methods-inventory.jsonl.gz`
静态清单（不运行目标即可产出）：每个方法一行，含落盘 IL 的形态分类
（`real` / `throw` / `vm` / `none`）与自定义特性名。

### `_out-il.tsv.gz`
回填后程序集里各方法体的实际 IL，用于比对验证。

## 统计可信度

| 项 | 可信度 | 说明 |
|---|---|---|
| 方法总数 52,948 | 高 | 直读 ECMA-335 元数据 |
| 真实 IL 42,153 | 高 | 运行时从 JIT 入口捕获，形态自校验 |
| HVM 桩 7,847 | 高 | 16 字节模式精确匹配 |
| 局部变量个数 23,303 | 中 | 由 IL 指令边界推出（`ldloc/stloc` 最大序号 + 1） |
| EH 子句 278/409 | 中 | 按标准段头 + 边界校验恢复 |
| 回填等价 28,878（68.5%） | 中 | token 掩码后的指令级比对；其余含同名重载配对噪声 |

## 已知限制

1. **7,847 个方法被 HVM 虚拟化** —— IL 只剩 `ldc.i4 progid; ldc.i4 idx; call VM派发器; ret`，
   逻辑在 DNGuard 的 VM 字节码里（加密段 `.hvm0`，3.06 MB，熵 7.95）。
   反编译结果里表现为 `ZYXDNGuarder.a(...)` 的 DVM 调用。
2. **局部变量类型是占位值** —— 保护器不给 locals 签名（`cbSig` 恒为 0），
   本项目按槽位数造 `ELEMENT_TYPE_OBJECT`，具体类型由 ILSpy 从使用点推断；
   `ref` / `struct` 语义可能丢失。
3. **约 1,293 个方法从未被 JIT** —— 没有真实 IL，落盘仍是抛错桩。
4. **部分指令被降级为 `nop`** —— 保护器摧毁了部分元数据，未回填方法的原体里
   存在操作数解析为空的指令（dnlib 无法写盘），写盘兜底时降级处理。
   只影响我们没抓到 IL 的方法。
5. **回填后的程序集不可直接运行** —— 原生运行时 `Mass.Runtime64.dll` 与各程序集里的
   DNGuard 保护段无法重建。产物用途是**阅读与分析**。
6. **字符串字面量** —— `#US` / `Constant` 堆里被摧毁的字面量会表现为空串或乱码；
   本项目抓到的 IL 中的 `ldstr` token 指向的字符串**多数完好**（含中文配置项）。
7. **原生侧另有独立的元数据保护**（与托管侧无关，见目标 native 库）：
   节名 XOR 0xBB、符号名等长随机替换（不可逆）等。本仓库聚焦托管侧的 DNGuard HVM。
