# 骨架生成器（MassSkeleton）：进展与剩余错误清单

> 目的：让**全部 11 个程序集**都变成「可编译 + 缺口显式标注」的工程。
> 本文记录一次**失败尝试**（文本中和）与当前**元数据生成路线**的精确状态。

---

## 1. 失败尝试：对反编译文本做「成员体中和」——已放弃

思路：桩体本身是合法 C#（`throw new Exception(...)`），所以只要把**反编译残留**所在的成员体
换成干净占位，文件就能编译。

做法（`tools/analysis/neutralize_bodies.py`）：自驱动循环 —— 编译 → 取 `error CS` 的
(文件, 行) → 找到包裹该行的成员体 → 换成占位 → 重编。

**结果：越修越坏。**

| 轮次 | 错误数 | 本轮中和处数 |
|---|---|---|
| 0 | 24,026 | 4,000 |
| 20 | 20,123 | 4,000 |
| 39 | 15,744 | 4,000 |
| 结束时累计中和 | —— | **约 16 万处**（74,266 个体 + 85,734 行） |

中和了 16 万处，错误只从 24,026 降到 15,744，且**过程中一度反弹**。

**根因**：反编译产物的**花括号本身就不平衡**（残留把结构破坏），
所以任何基于「向前找最近的 `{` 并配对」的文本重写都会把注入内容放到**错误的嵌套层级**
——典型症状是编译器报 `成员声明中的标记"throw"无效`、`应输入类型、命名空间定义或文件尾`、
`顶级语句必须位于命名空间和类型声明之前`。

⇒ **对结构已损坏的文本做结构性重写是不成立的。** 该脚本保留在仓库内作为记录，
但**不再使用**。

## 3. 已修掉的错误类别（7 类）

| 类别 | 症状 | 修法 |
|---|---|---|
| 编译器生成名 | `<>f__AnonymousType5` 以 `<` 开头 | `Id()` 把非字母数字下划线一律映射为 `_` |

| 事件声明 | `CS1055 应为 add/remove 访问器` | 改发 `{ add { } remove { } }` |
| `const` 字段 | `CS0145 常量字段要求提供一个值` | 改发 `static readonly` |

## 4. 剩余错误清单（本轮结尾实测，**尚未编译通过**）

```
CS0246  类型或命名空间找不到      38,428
CS0673  System.Void 不能当类型    16,122
CS0100  参数名重复                14,398
CS0111  成员重复定义               7,408
CS0535  未实现接口成员               848
CS0106  修饰符无效                   613
CS...   （另有若干小类）              ~1,700
```

对应的**待修点**（下一轮的确定任务）：

1. **`CS0246`（最大头）**：引用名解析。需逐例确认是「点分名拼装错误」还是「类型确实缺失（需 shim）」。
2. **`CS0673`**：`System.Void` 出现在参数/字段类型位置（编译器生成的 `ref Void` 签名）→ 应替换为 `object`。
3. **`CS0100`**：参数名为空或重复（元数据里参数可无名）→ 需按序号生成 `p0/p1…`。
4. **`CS0111`**：同名同参方法（DNGuard 的同名槽位池）→ 需按 token 追加后缀。
5. **`CS0535`**：`IAsyncStateMachine` 等接口的实现体被占位后不满足接口 → 需为接口成员发 `public` 实现。

## 6. Round 13 更新：错误数 79,644 → 1,092（降 98.6%）

### 6.1 本轮修掉的 8 类（累计 15 类）

| 类别 | 症状 | 修法 |
|---|---|---|
| **命名空间缺失** | 76,040 条 `未能找到类型或命名空间名"Mass"` | **生成器从未发射 `namespace` 声明**！补上包裹（`RootNs` 包装 + `NsStr` 净化） |
| `CS0673` 16,122 | `System.Void` 出现在参数/字段类型位 | `TN2` 一律不输出 `System.Void`（改 `object`）；`RS()` 单独保留 `void` 返回 |
| `CS0100` 14,398 | 参数无名/重名 | 参数名唯一化，无名或重复者按序号生成 `p0/p1…` |
| **隐藏 `this`** | 实例方法多出一个自类型首参（`GetHashCode(Self p0)`） | dnlib 的 `MethodDef.Parameters` **含隐藏 `this`**；按「首参类型 == 声明类型」剔除 |
| `CS0111` >7,000 | 成员重复定义 | ① 方法按 **C# 级签名**（名字 + 参数**类型**，不含参数名）去重；② 名字净化后撞名追加 `_2/_3`；③ 字段/属性/事件共用一个名字集合 |
| `CS0106` 585 | `{ static get; }` 访问器里放 `static` | `static` 提到属性类型之前 |
| `CS0515/CS0722/CS0311/CS0214` | 静态构造函数带修饰符 / `static` 类型不可作类型用 / 指针需 unsafe | `.cctor` 不带修饰符；不再把类型标 `static`；指针类型改 `System.IntPtr` |
| **跨程序集同命名空间撞名** | `<>f__AnonymousTypeN`、**`ZYXDNGuarder`（每个程序集各有一个）** 在两份骨架里同名 | 预扫描所有程序集顶层全名 → 撞名者按**目标程序集标识**加后缀（`_aNNN`） |

> ★ 其中两条是**根因级**的：① 生成器漏发 `namespace`（一次贡献 76,040 条错误）；
> ② dnlib 的 `Parameters` 含隐藏 `this`。

### 6.2 环境限制（重要）

**`Mass.WinUI`（WinUI3）骨架无法在 Linux 上编译**：
`Microsoft.WindowsAppSDK` 的 `buildTransitive/*.targets` 要求 `Microsoft.Windows.SDK.NET.Ref`，
即 **Windows SDK 引用包**，Linux 上不可用（实测报错见下）。

```
error : This version of the Windows App SDK requires Microsoft.Windows.SDK.NET.Ref or later.
        Please update to .NET SDK 8.0.109/8.0.305/8.0.402 (or later).
```

⇒ 「整体可编译」**必须分平台**：WinUI 相关部分只能在 Windows 上构建。
Linux 上可行的部分是 10 个非 WinUI 程序集。

### 7.2 明确的保真度取舍（全部可从元数据查回）

为了「可编译」而**主动放弃**的声明信息，逐条登记：

| 放弃项 | 原因 | 影响 |
|---|---|---|
| 基类列表 | 否则派生成员遮蔽基类抽象成员（CS0533/CS0534） | 继承关系需从元数据查回 |
| 类/结构体的接口列表 | 否则报未实现接口成员（CS0535/CS0534） | 同上 |
| 泛型 `where` 约束 | 否则类型实参不满足约束（CS0311） | 同上 |
| 事件 → 字段 | 否则 `add_`/`remove_` 保留名冲突（CS0082） | 事件语义需查回 |
| `.cctor` 静态构造体 | 一律占位 | —— |
| `const` → `static readonly` | 否则常量字段缺值（CS0145） | 常量值需查回 |

> **这些取舍不影响骨架的用途**：类型与成员的**名字、签名、数量**完整可编译，
> 被放弃的只是修饰性信息，且**全部可通过 dnlib 从原 DLL 逐项查回**。

### 8.2 一个重要的踩坑记录

给「泛型类型的嵌套类型」补父层实参时，我一开始**也给顶层类型补了自身实参**，
于是与 `GenericInstSig` 路径追加的实参叠成了 `X<object><Y>` → **一次性引入 1,786 个语法错误**。
回退「顶层补实参」后立即回到 0。**教训：类型名打印的多个路径不能都追加实参，必须只在一处补。**
