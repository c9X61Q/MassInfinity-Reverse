# 可编译性：缺口台账与首个可编译产物

> 目标：把「能直接编译出 Mass 的源码」变成**可枚举、可核对**的工程。
> 本文记录：① 逐成员缺口台账；② 权威依赖清单；③ 第一个**编译通过**的重建产物。

## 2. 文件级洁净度分类（三个判据）

判据：**桩标记**（同上）、**反编译残留**（`/*Error near IL_`、`Stack underflow`、
`Expected X, but got`、`Member reference must be method`）。

| 桩标记 | 反编译残留 | 文件数 | 含义 |
|---|---|---|---|
| 无 | 无 | **110** | 可用（本轮的编译输入） |
| 无 | 有 | 26 | **假干净** —— 无桩但体是 ILSpy 失败产物 |
| 有 | 无 | 12 | 纯桩文件 |
| 有 | 有 | 1,043 | 两者都有 |

> ⚠️ 教训：「无桩标记」**不足以**判定可用。`Filterable.cs` 就是假干净的例子 ——
> 无任何残留标记，但构造函数体是 `_003C_003Ef__AnonymousType0<>…` 这种无效表达式。
> 因此洁净度必须**以能否编译为准**（见 §4）。

## 4. 首个可编译产物（本轮成果）

工程：`reconstructed/MassReconstructed.csproj`

```
输入：110 个「无桩标记 + 无反编译残留」的反编译文件（raw/**）
      + 3 个缺口占位声明文件（shims/**，明确标注「不是官方实现」）
      + 上表 10 个 NuGet 包
结果：0 警告 / 0 错误 → 产出 MassReconstructed.dll（114,176 字节）
```

### 4.1 为编译而补的缺口（全部只有 4 个符号）

| 缺失符号 | 位置 | 处置 |
|---|---|---|
| `Mass.Game.Proxy.Network.Converters.InterfaceConverter<T>` | 被保护方法集内 | `shims/InterfaceConverter.cs`（占位，调用即抛） |
| `Mass.Game.Proxy.Network.Optional<T>` | 被保护方法集内 | `shims/Optional.cs`（占位） |
| `Mass.Game.Proxy.Minecraft.Connection` | 被保护方法集内 | `shims/Connection.cs`（占位） |
| `Filterable<T>` 构造函数体 | **假干净**（无标记但体无效） | 保留真实字段声明，体替换为占位 |

> **这 4 个符号就是「可编译 110 文件」的全部缺口** —— 缺口是可枚举的，不是黑箱。

### 4.2 复现命令

```bash
cd reconstructed
dotnet build          # 需要 .NET 8+ SDK；会自动 restore 上表依赖
```

## 5. 下一步（把 110 文件扩到全部 1,191 文件）

1. **按台账逐项目推进**：先做桩占比最低的 `Mass.Common`/`Mass.Domain`，
   再做 `Mass.WinUI`（最大）。
2. **假干净文件（26 个）优先复核**：它们无残留标记但体可能无效，必须逐个人工确认。
3. **高桩类以 SDK 为参照重写**：`DesktopSession`、`DesktopAuthentication`、`NetEaseDesktop`、
   `MassService` —— 上游 `refs/upstream-mass-sdk` 是这一层的权威参照。
4. **每并入一批就把新缺口写进 `shims/` 并在本文登记**，保持"缺口可枚举"。
5. **被保护方法的语义缺口不可填补**（见 `VM-机制与下一步.md` §22/§25），
   这部分只能以「重写」而非「还原」的方式实现，须在文档中始终标注清楚。
