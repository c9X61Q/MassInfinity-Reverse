## 1. 表结构

```c
struct DescTable {        // 恰 64 字节
    uint32_t packed[16];  // packed[i] = (RID << 4) | table_nibble
};
// 还原 token: token = TABLE[packed[i] & 0xF] | (packed[i] >> 4)
// TABLE = Mass.Runtime64.dll 内 0x1800602c0（9 项）
//   0 TypeDef  1 TypeRef  2 MethodSpec  3 Field  4 MethodDef
//   5 MemberRef 6 0x2B    7 StandAloneSig  8 #US
```

**存放位置**：每个托管程序集的 `.text` 里**恰好一张**，以**明文**嵌在约 50–60% 的
高熵加密区内（Mass.WinUI 在 file `0x18530` / RVA `0x1a330`）。

**生成器读法**（`Mass.Runtime64.dll` `0x180017088` 起，真实代码）：
```asm
mov 0xd8(%rbx),%rax ; mov 0x10(%rax),%ecx ; and $0xf,%eax ; shr $0x4,%ecx
lea 0x1800602c0,%rdx ; mov (%rdx,%rax,4),%r8d ; or %ecx,%r8d   ; → token
mov $0x80,%edx ; call 0x18001d830                              ; emit(stsfld, token)
```
生成器**固定**使用槽 **0 / 4 / 5 / 6 / 11 / 12 / 14 / 15**；
`cmpl $0x0,0x2c(%rax)`（= 槽 11 是否存在）是可选分支开关；
**槽 8 在 12/12 运行时样本中恒为 0**。

## 3. 与运行时捕获的桩体逐条吻合

运行期 JIT 处捕获的受保护方法体（清除 bit23 后）：

```cil
ldnull ; ldc.i4.0 ; ldc.i4.0 ; newobj Exception::.ctor(string)   ; ← 槽 2/3 + 0xb26
ldsfld ZYXDNGuarder.a                                            ; ← 槽 4
call   MethodBase::GetCurrentMethod()                            ; ← 槽 13  ✅
ldc.i4 <k> ; ldc.i4 <progid> ; ldc.i8 <desc>
newobj IntPtr::.ctor(long)                                       ; ← 槽 3   ✅
ldc.i4.s 15 ; call ZYXDNGuarder.a ; calli                        ; ← 槽 6 + 槽 5（calli 签名）
ldnull ; ret
```

**桩模板引用的每一个成员都在这张表里** ⇒ 描述符表 = **「该程序集生成的桩模板所需的成员集合」**。
每程序集只有一张，是因为各程序集的 RID 不同，**语义上是同一组入口**。

---

## 4. 结论

1. 描述符表**不是**每方法的"程序"或"原始 IL"，而是**每程序集的成员引用表**。
2. 受保护方法的桩是**模板化**的：所有方法共用同一骨架，
   只在 `k`、`progid`、`desc` 三个常量上不同。
3. 因此**不存在**"从描述符还原每个方法的 IL"这条路径 —— 描述符里没有方法语义。
   方法语义只可能存在于运行时被 DNGuard 解释/执行的加密数据中，
   而每个桩 `calli` 到达的原生入口（`sub_180001310`）**只做 `cmp [rcx+0x3b8],0`
   然后返回 0**（REA 权威，见 `VM-机制与下一步.md` §22）。
