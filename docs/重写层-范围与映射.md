# 那部分是什么，以及重写到什么程度

> **口径先立住**：受 DNGuard HVM 保护的方法，其语义**不存在于任何可提取的产物中**（五条证据链见
> [`VM-机制与下一步.md`](VM-机制与下一步.md) 与 `docs/骨架生成器-进展与剩余错误.md` §6–§8）。
> 所以下面所有「重写」都是**按契约重新实现**，**不是还原**。任何地方都不会把重写说成还原。

数据文件：[`../data/gap-ledger.tsv.gz`](../data/gap-ledger.tsv.gz)（逐成员）、
[`../data/stub-buckets.tsv.gz`](../data/stub-buckets.tsv.gz)（按类的分桶）。

## 1. 那部分是什么：33,514 个桩拆成四桶

「76.5% 不可还原」这个数字听着吓人，但**拆开看，其中 33.7% 根本不是应用逻辑**。

## 2. 重写到什么程度（只看已交付的）

重写层代码：**源码仓库** [`impl/MassInfinity.Rewrite`](https://github.com/c9X61Q/MassInfinity-Source/tree/main/impl)（net8.0，**0 警告 0 错误**）。

| 增量 | 覆盖什么 | 依据的契约 | 验证 |
|---|---|---|---|
| **① 服务协议层** | 20 个端点（base/security/desktop 登录 8/mobile 登录 7/instance 3）+ SignalR 三事件（`Progress`/`GameInstance`/`Disposed`）；snake_case + `{code,msg,data}` 信封 | 官方客户端 SDK（`massarolucien/Mass.Sdk`，**MIT**，原文副本在 `refs/`） | 编译通过；**未与原始客户端做过逐端点比对** |
| **② Bedrock 包层** | `ClientPayload` **41 字段** + `LoginPacket` 帧（`i32(BE)` 协议号 + 两个 VarInt 长字符串）+ JWT 拆装 + 皮肤负载 **zlib** | ① 反编译**元数据声明**里 41 字段的名字与顺序；② MC Bedrock 公开协议规范 | **31 项往返自检全部 PASS**（含 zlib+JWT 全链路取回） |

自检怎么跑：`cd impl/MassInfinity.Rewrite.SelfTest && dotnet run`

> ⚠️ 自检测的是「**本实现自洽**」（写进去能读回来），**不是**与原始客户端的行为等价性 —— 后者无法验证，
> 因为原始方法体不存在。

## 4. 还没做的

1. **D 桶剩余大量类**：`Mass.Game.Proxy` 的包编解码（`TextComponent`/`CommandNode`/`ClientboundJoinGamePacket`…）、
   `Mass.Game.Launcher`（进程/参数/版本管理）、`Mass.Domain.*` 的实体 DTO —— 都是有字段声明可查的，
   但工作量大，且其中相当一部分**只有拿到公网协议规范或实际抓包才能写对**。
2. **B 桶 6,399 个异步状态机**：需要业务语义，不是格式问题。
3. **A/C 桶**：不需要写（A 是诱饵，C 可工具重生成）。
4. **行为等价性验证**：需要真实服务端 + 抓包，目前没有。

## 5. 元数据的硬数字（比台账更准）

台账是从**反编译文本**统计的；直接从**元数据**统计更权威。工具：`tools/MassStats`（dnlib）。

```

  属性访问器  6,657   ← 编译器生成语义 → 可机械重写 ✅
  构造函数    1,534
  可读名方法  1,263   ← 真正「有名字可写」的（含 Read/Write/Connect/Encrypt/Decrypt/ProcessBytes…）
  混淆名方法 36,802   ← 69.5%，名字本身就是垃圾 → 硬边界 ❌
属性总数 3,193
```

**可读名方法 Top**（`mass-ildump` 台账侧统计）：


## 6. 「写完」到底能写完什么

| 层 | 规模 | 依据 | 状态 |
|---|---|---|---|
| **属性 / 实体层** | 3,193 属性（780 类型/枚举） | 访问器体由编译器生成 → **按构造正确** | ✅ **已交付**：`impl/MassInfinity.Rewrite.Generated`（0 错误，全量反射往返 720 类全部一致） |
| **Bedrock 包层** | `ClientPayload` 41 字段 + `LoginPacket` 帧 | 元数据声明 + 公开协议规范 | ✅ **已交付**：`Bedrock/`（33 项自检全通过） |
| **服务协议层** | 20 端点 + SignalR 三事件 | 官方 SDK（MIT）契约 | ✅ **已交付**：`Client/`（编译通过；未做逐端点比对） |
| **状态机 / 框架管线** | `MoveNext` 等 745 + 框架管线 ~90 | 编译器生成 | ⚪ 不该手写：用 `async` / 记录类型重写对应方法即可自动得到 |
| **剩余具名方法** | ~1,263 − 上述 ≈ 数百 | 部分有规范（加密/传输），部分需抓包 | ⏳ 未做 |
| **混淆名方法** | **36,802（69.5%）** | **名字本身就是垃圾** | ❌ **硬边界**：无法写出"同名"实现，也无从知道该实现什么 |

### 结论

**"写完"在这里的真实含义**：把**由契约或构造决定语义**的部分全部写完（属性层 + 包层 + 服务协议层，已交付），
并把**由混淆名决定的 69.5%** 明确标为硬边界 —— 那部分的语义不在数据里，重写它等于凭空编造，所以**不写**。

## 7. 仍未覆盖

1. **数百个剩余具名方法**（`Connect`/`Encrypt`/`Decrypt`/`ProcessBytes`/`ReadFromBuffer`…）—— 加密与传输层，
   部分可据算法名与协议规范写出，但需要**抓包或规范来源**才能保证正确。
2. **`Mass.Game.Proxy` / `Mass.Game.Launcher` 的业务逻辑** —— 名称可读性差，多数属混淆名。
3. **行为等价性验证** —— 需要真实服务端 + 抓包，目前没有。
